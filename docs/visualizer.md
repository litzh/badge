# 三源融合粒子屏保（Lumina）

当前版本 v0.5.0 在 10 秒无交互后显示 80 个带拖尾的彩色粒子。画面保持黑底，没有常亮文字、
表盘或边框。安静、静止时仍持续缓慢游动；三个传感器共同影响同一画面。

## 输入与画面

| 输入 | 映射 | 响应方式 |
| --- | --- | --- |
| 麦克风总能量 | 粒子活跃程度和发光强度 | 快速上升、缓慢回落，短促声音保留峰值 |
| 低、中、高三个宽频段 | 三组粒子的轨道起伏和扩张 | 16kHz 双通道，每 256 帧分析一次 |
| 加速度 X/Y | 粒子群中心朝倾斜方向偏移 | 平滑重力分量，限制偏移范围 |
| 绕 Z 轴旋转 | 顺时针或逆时针旋流 | 随陀螺仪读数平滑变化 |
| 摇晃 | 粒子短暂散开后重新聚拢 | 加速度模长偏离 1g 触发并自然衰减 |
| QMI8658 芯片温度 | 青绿 → 蓝紫 → 红 → 琥珀色调 | 约每秒读取，约 12.5 秒尺度平滑 |

温度色域按 20–32°C、32–40°C、40–50°C 分段插值，范围外保持端点。
这是艺术配色，不表示温度安全等级。芯片温度受到板上发热影响，不是室温计。
这里的“熵”指传感器带来的视觉扰动；本实现不把这些输入当作密码学随机源。

## 交互与资源

- 触摸、BOOT、PWR、echo、亮度设置等交互可从屏保唤醒主页，屏保采音随后停止；
  0.7.0 起 BOOT 会直接启动对话录音，PWR 在亮屏时则手动熄屏。
  倾斜、摇晃、声音和温度变化本身不唤醒，否则无法在屏保中交互。
- 实际亮度为 `min(保存亮度, 128)`，唤醒恢复原亮度，不反复写 NVS。
- 屏保最多运行 5 分钟，随后面板休眠、停止动画和采音；触摸或按键可以唤醒。
  低电时跳过屏保，详情见 [电池管理](power-management.md)。
- 使用 466×466 RGB565 PSRAM 缓冲区（434,312 字节），每帧衰减旧像素再绘制新粒子。
  几何约束把粒子限制在可见圆内，静止时也不会留下永久轨迹。
  v0.4.1 将传屏拆成两行一组，每组独立设置地址窗口，避开长连续 QSPI 写入。
- 目标绘制间隔 67ms；真实速度受全屏 QSPI 传输限制。v0.4.1 条带传输约 10–11 帧/秒，
  与较轻的旧版 7 光点屏保相比会增加计算、采音与传屏功耗。
- 麦克风在独立任务中采样，动画和 HTTP 运行于主循环。录音不保存、不上传；
  HTTP 只公开能量、温度、动作和性能统计。
- 三频段由去直流及一阶滤波器生成，频段有重叠，适合驱动画面，不是精密频谱分析仪。

降低亮度和避免固定图形用于减少 OLED 固定区域长期高亮，不能消除老化。
屏保仍保持 Wi-Fi 在线，不是深度睡眠模式。新版续航需单独测量。

## 失败处理

麦克风样本过期时声音输入归零，运行时启动/读取失败每 3 秒重试。
IMU 数据过期使用中性重力，温度读取失败保持此前平滑色调，动画继续自主运动。
PSRAM 缓冲区分配失败则回退到旧版 7 光点屏保。
`GET /status` 与 `GET /visualizer` 可查看错误和数据年龄，均不唤醒。

## 开发与验证

主要文件：`audio_features.h`（音频特征）、`microphone.cpp`（硬件采样）、
`particle_field.h`（平台无关粒子与渲染）、`visualizer.cpp`（输入整合和显示）。

```sh
uv run validation/render_frame.py
uv run validation/device_visualizer.py http://DEVICE_IP
uv run validation/device_screensaver.py http://DEVICE_IP
```

第一个命令编译实际 C++ 引擎并执行音频和粒子测试，生成
`validation-output/lumina.png`。后两个命令会唤醒设备检查进入/退出屏保，
亮度测试最终恢复原值，勿在进行续航对比实验时运行。

2026-09-17，v0.4.2 验证记录：

- Core 3.3.2-cn 构建 1,325,239 字节（42%），静态 RAM 58,280 字节（17%）；
  USB 刷写和哈希校验通过，设备报告 `badge-0.4.2`。
- 唤醒停止采音、10 秒后恢复屏保与 16kHz 双通道采样、温度读取、查询不唤醒均通过。
  实机温度约 40.7°C，音频和 IMU 样本未超时。
- 连续查询约 5.1 秒增加 50 帧；最后一次画面含 8,148 个非黑像素，
  面板实际亮度 128，保存亮度仍为 255。帧率随传屏和请求负载变化。
- C++ 测试覆盖静音、直流抑制、低中高频、反相双麦、10 万步粒子边界和数值有效性、
  倾斜响应、缓冲区越界哨兵、圆形裁切及完整/奇数高度条带传输。
- 已检查实际 C++ 渲染的离线图像；用户目视确认文字稳定、提高亮度后粒子可见。
  实体 PWR/BOOT 全部动作未逐项人工验收；温度未做独立仪器校准。

亮度修复依据：旧版亮度 24 时画面已包含约 8,000 个非黑像素，但看起来接近熄屏；
保持同一画面提高至 128 后粒子可见。因此条带传输不是解决黑屏观感的原因。
保留像素统计用于区分空画面与显示亮度问题，软件统计不能替代面板目视验证。

直接体验：等 10 秒，拍手或播放音乐，再缓慢倾斜、转动、轻摇设备。
温度配色变化较慢，不需要为了观察颜色专门加热设备。
